# Презентация

Презентация — это аргумент, разложенный по экранам, а не документ, порезанный
на куски. Поэтому работа начинается не с оформления, а с того, что зритель
должен понять и сделать. Красивые слайды без линии рассуждения читаются как
набор картинок, а нестройный текст не спасает никакая анимация.

## 1. Сначала линия рассуждения

Ответь себе на три вопроса и не переходи дальше, пока нет ответов:

- **Что зритель должен сделать после?** Одобрить бюджет, выбрать вариант,
  подписать, перестать спорить. Если ответа нет, презентация не нужна —
  нужен документ.
- **Во что он должен поверить, чтобы это сделать?** Это и есть список
  слайдов: одно убеждение — один слайд.
- **Чем вы это доказываете?** Цифра, график, цитата, демонстрация. Слайд
  без доказательства — это лозунг.

Дальше напиши **только заголовки**, подряд, без оформления. Заголовок —
это утверждение, а не тема. «Рынок» — тема. «Ниша занята тремя игроками,
и ни один не закрывает размерную сетку» — утверждение.

Прочитай заголовки подряд. Если из них складывается рассуждение — можно
верстать. Если нет — слайды не спасут.

Правило: если в заголовке появилось «и», это два слайда.

## 2. Как делать

Формат по умолчанию — **HTML-презентация одним файлом**. В ней работает
анимация, она открывается в любом браузере, её можно отправить ссылкой
и распечатать в PDF.

PPTX нужен только тогда, когда файл будут редактировать без вас или
этого требует регламент. Тогда используй скилл `pptx`, а здесь возьми
раскладку и правила типографики.

Основа — `assets/template.html`. Скопируй его и заполняй; вся механика
уже внутри: навигация, прогресс, заметки докладчика, режим обзора,
печать. Не пиши свой раннер: там десяток мелочей, каждая из которых
ломает показ в самый неподходящий момент.

```bash
cp .claude/skills/deck/assets/template.html deck.html
# заполнить слайды
python3 .claude/skills/deck/scripts/build.py deck.html   # PDF + контактный лист
```

## 3. Анимация: три законных повода и ничего больше

Движение на слайде оправдано ровно в трёх случаях:

1. **Управление порядком чтения.** Пункты появляются по одному, пока
   докладчик о них говорит. Зритель не убегает вперёд и не читает вместо
   того, чтобы слушать.
2. **Показ изменения.** Было и стало, рост во времени, перестроение
   схемы. Движение здесь несёт смысл, который в статике теряется.
3. **Граница раздела.** Переход между частями — единственное место,
   где уместен заметный эффект.

Всё остальное — вылеты, вращения, отскоки, посимвольное появление —
это шум. Он крадёт внимание у того, ради чего слайд сделан.

Числа, которые работают:

| что | длительность | кривая |
|---|---|---|
| появление пункта | 180–250 мс | ease-out |
| перестроение, морфинг | 350–500 мс | ease-in-out |
| смена раздела | 500–700 мс | ease-in-out |

Дольше 800 мс не делай ничего: на первом показе это эффектно, на втором
раздражает, а докладчик смотрит свою презентацию десятки раз.

Два обязательных условия:

- **`prefers-reduced-motion` уважается.** В шаблоне это уже учтено —
  анимация выключается целиком, слайды остаются читаемыми.
- **Анимация не нужна для понимания.** В PDF движения нет, все шаги
  показаны сразу. Если слайд без анимации перестаёт читаться, он
  построен неверно.

## 4. Оформление

Подробности — в `references/design.md`. Главное:

**Типографика.** Два размера делают всю работу: заголовок и текст.
Третий — для надзаголовка. Минимальный кегль основного текста на холсте
1920×1080 — 28 px; всё мельче не читается с пятого ряда. Строка не длиннее
75 знаков.

**Цвет.** Один акцент, и он достаётся тому единственному, ради чего сделан
слайд. Фон либо почти белый, либо почти чёрный — последовательно, не через
слайд. Контраст проверяется расчётом, а не глазом: проектор смывает цвет,
поэтому целься в 7:1, а не в минимальные 4,5:1.

**Сетка.** Холст 1920×1080, поле 80 px, 12 колонок. Всё выравнивается
по ней, включая картинки.

**Графики.** Один график — одно утверждение. Подписывай линии прямо
на них вместо легенды. Всё, кроме главного, делай серым. Если в сессии
есть скилл `dataviz`, читай его перед первым графиком.

## 5. Проверка перед отправкой

Собери PDF и контактный лист и посмотри на них. Это не формальность:
переполнение текста, съехавшие подписи и слипшиеся графики видны только
на отрендеренных слайдах.

```bash
python3 .claude/skills/deck/scripts/build.py deck.html
```

Скрипт кладёт рядом `deck.pdf` и `deck-contact.png` — все слайды сеткой.
Плюс печатает предупреждения: переполнение, низкий контраст, слишком
мелкий шрифт, слайды без заголовка.

Что проверить самому:

- заголовки подряд читаются как рассуждение;
- ни на одном слайде текст не вылезает за поле;
- в PDF видны все шаги анимации;
- на содержательный слайд уходит 1,5–2 минуты речи — сверь с регламентом;
- на слайде не больше одного акцентного цвета.

## 6. Чего не делать

**Не переносить документ на слайды.** Абзацами на экране не выступают.
Если материала много, сделай раздаточный файл отдельно, а на слайдах
оставь то, что нужно показать.

**Не ставить анимацию на каждый элемент.** Если анимировано всё,
не выделено ничего.

**Не набивать слайд списком из восьми пунктов.** Больше пяти строк —
значит, слайд про две разные вещи.

**Не выдумывать цифры.** Каждое число на слайде должно быть откуда-то.
Если источника нет, так и напиши на слайде — оценка честнее точности,
которой нет.
