# ПрофИД — сайт

Production-сборка сайта внешнего отдела ПТО. Astro 5 + TypeScript + чистый CSS,
статика без клиентского рендеринга.

---

## Быстрый старт

```bash
npm install
npm run dev        # http://localhost:4321
```

```bash
npm run build      # сборка в dist/
npm run preview    # посмотреть готовую сборку
```

**Важно.** Русская типографика применяется на этапе сборки. В `npm run dev`
неразрывных пробелов не будет — это нормально. Проверять текст всегда на
`npm run build && npm run preview`.

Требуется Node 18+ (проверено на 22).

## Что заменить перед публикацией

Всё, что нужно подставить, лежит в одном файле — **`src/data/site.ts`**.
Правится там, расходится по всему сайту: футер, контакты, микроразметка, формы,
политика конфиденциальности.

| Поле | Что подставить | Где отзовётся |
|---|---|---|
| `legalName` | точное наименование юрлица | футер, политика, микроразметка |
| `inn`, `ogrn` | реквизиты | футер, политика, `taxID` в разметке |
| `streetAddress`, `postalCode` | адрес, если он публичный | `PostalAddress` в микроразметке |
| `phone`, `phoneHuman` | рабочий номер (E.164 и для показа) | шапка, футер, полоса связи, формы |
| `email` | рабочая почта | футер, контакты, политика |
| `telegram`, `telegramUrl` | реальный аккаунт | контакты, полоса связи, `sameAs` |
| `domain`, `url` | боевой домен | canonical, Open Graph, sitemap, robots |
| `analytics.yandexMetrika` | номер счётчика | подключает Метрику с вебвизором |
| `formEndpoint` | URL приёмника заявок | см. ниже |
| `stats` | четыре цифры первого экрана | главная, страница о компании |

Пока `inn` пуст, в футере видна красная пометка «реквизиты не заполнены», а на
странице политики — блок с перечнем незаполненных полей. Это сделано намеренно,
чтобы нельзя было опубликовать сайт, не заметив пропуска.

**Домен также прописан в двух местах, которые не читают `site.ts`:**
`astro.config.mjs` (константа `SITE`) и `public/robots.txt` (`Host` и `Sitemap`).

**Прайс.** `src/data/prices.ts` — 28 позиций, собранных по рыночным ориентирам,
а не подтверждённых владельцем. Пройти по таблице целиком до запуска рекламы.
Подробности — в `DECISIONS.md`, пункт 6.

**Объекты.** В `src/content/objects/*.md` поля `year` и часть паспорта помечены
`TODO`. Полный список — в `REPORT.md`.

## Подключение форм

Сейчас формы работают на заглушке: валидация, маска, honeypot, ограничение
частоты и экран благодарности отрабатывают полностью, но заявка никуда не уходит
и пишется в консоль браузера.

Чтобы включить отправку, задайте `formEndpoint` в `src/data/site.ts` — адрес
серверной функции, которая примет JSON и разошлёт заявку.

**Что приходит в приёмник:**

```json
{
  "name": "Иван",
  "phone": "+7 916 123-45-67",
  "email": "inbox@company.ru",
  "service": "/oformlenie-id",
  "message": "монолит, 4 секции, ИД не велась с апреля",
  "consent": "on",
  "company_site": "",
  "_kind": "zayavka",
  "_page": "/oformlenie-id"
}
```

- `_kind` — `zayavka`, `call` или `checklist`;
- `_page` — с какой страницы пришла заявка;
- `company_site` — honeypot. **Если поле непустое, это бот: заявку надо молча
  отбросить.** Браузер такие отправки и так не выпускает, но серверную проверку
  делать обязательно.

**Что должен делать приёмник** (по разделу 7 ТЗ):

1. отправить сообщение в Telegram **обоим** получателям — владельцу и сотруднику
   в Москве (разные часовые пояса, это принципиально);
2. продублировать на почту;
3. при `_kind: "checklist"` — сразу выслать файл чек-листа письмом;
4. вернуть код 2xx. Любой другой код покажет пользователю сообщение с
   предложением написать в Telegram.

Точка вызова помечена в коде: `src/scripts/ui.ts`, комментарий
`TODO(разработчик)`.

CORS: приёмник должен разрешать запросы с боевого домена.

## Аналитика и цели

Метрика подключается одним полем `analytics.yandexMetrika`. Пока оно пустое,
никакие счётчики не грузятся — на скорость это не влияет.

Цели уже отправляются из кода, настроить их нужно в интерфейсе Метрики
по этим идентификаторам:

| Цель | Когда срабатывает |
|---|---|
| `form_send` | отправка заявки или заказа звонка |
| `checklist_send` | отправка формы чек-листа |
| `tel` | клик по телефону |
| `tg` | клик по Telegram |
| `mail` | клик по почте |
| `calc_use` | первое взаимодействие с калькулятором |
| `scroll_75` | прокрутка до 75% страницы |
| `popup_show` | показ всплывающего окна |

## Деплой

Сборка — статика. Подойдёт любой хостинг или CDN: содержимое `dist/` кладётся
в корень сайта.

**Настроить на стороне сервера:**

- HTTPS с валидным сертификатом;
- 301 с `www` на без `www`;
- 301 с `http` на `https`;
- адреса без завершающего слэша (`/ceny`, не `/ceny/`) — сборка настроена
  на `trailingSlash: 'never'`;
- `404.html` как страница ошибки;
- сжатие gzip или brotli для `.html`, `.css`, `.js`, `.svg`;
- долгий кэш для `/_astro/*` и `/og/*` (имена файлов содержат хеш),
  короткий — для `.html`.

Пример для Nginx:

```nginx
server {
    listen 443 ssl http2;
    server_name profid.ru;
    root /var/www/profid/dist;

    error_page 404 /404.html;
    gzip on;
    gzip_types text/html text/css application/javascript image/svg+xml application/json;

    location /_astro/ { expires 1y; add_header Cache-Control "public, immutable"; }
    location /og/     { expires 1y; add_header Cache-Control "public, immutable"; }
    location /        { try_files $uri $uri.html $uri/index.html =404; }
}

server {
    listen 443 ssl http2;
    server_name www.profid.ru;
    return 301 https://profid.ru$request_uri;
}

server {
    listen 80;
    server_name profid.ru www.profid.ru;
    return 301 https://profid.ru$request_uri;
}
```

**После выкладки:** отдать `sitemap-index.xml` в Яндекс.Вебмастер и Google
Search Console, подтвердить права, проверить `robots.txt` по боевому адресу.

## Как добавлять контент

**Статья в блог.** Создать `src/content/blog/slug.md`. Обязательные поля
описаны схемой в `src/content.config.ts` — сборка упадёт с понятной ошибкой,
если чего-то не хватает или `description` вышел за 120–180 знаков. Страница,
карточка в листинге, микроразметка `Article`, запись в sitemap и картинка для
соцсетей появятся сами.

**Услуга.** `src/content/services/slug.md`. Адрес совпадает с именем файла.
Добавить пункт в `src/data/nav.ts`, чтобы услуга попала в меню и подвал.

**Объект.** `src/content/objects/slug.md`. Заполненные строки паспорта
показываются, пустые пропускаются — прочерков в таблице не будет.

## Проверки

```bash
npm run build && npm run preview   # в отдельном окне

node scripts/audit.mjs    # текст без JS, вес, контраст, формы, разметка,
                          # метатеги, запрещённые обороты, типографика, ссылки
node scripts/checks.mjs   # 320 px, цели нажатия, работа без JS,
                          # prefers-reduced-motion
node scripts/shots.mjs    # скриншоты всех страниц: 1440 и 390
node scripts/shots.mjs --320   # добавить 320 px

npx html-validate "dist/**/*.html"
```

Скриншоты складываются в `shots/`. Отдельные страницы: `node scripts/shots.mjs
ceny blog`.

Playwright использует браузер, уже установленный в окружении. `playwright
install` запускать не нужно; путь при необходимости переопределяется
переменной `PW_CHROME`.

Результаты последнего прогона и честная самокритика по каждой странице —
в `REPORT.md`.

## Чего в проекте намеренно нет

- **Клиентского рендеринга.** Весь текст в исходном HTML: Яндекс исполняет
  JavaScript хуже Google, и это требование раздела 4 ТЗ.
- **Веб-шрифтов.** Системный стек, ноль запросов на шрифты, ноль скачков вёрстки.
- **Tailwind, Bootstrap, jQuery, UI-китов.** Дизайн-система живёт на токенах.
- **Фотографий и фонового видео.** Причина и что делать — `DECISIONS.md`, п. 2–3.
- **reCAPTCHA.** Запрещена ТЗ. Защита — honeypot и ограничение частоты.
