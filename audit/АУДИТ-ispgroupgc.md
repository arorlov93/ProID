## 2. Критично — чинить сегодня

### 2.1. Форма на `/contact` полностью закрыта фотографией

**Это не придирка и не эффект скриншота — проверено вычисленными стилями.**

Форма `#cf` существует, занимает 1090×828 px, имеет собственную тёмную подложку `ASIDE.cform` с фоном `rgb(20,25,34)`, девять подписанных полей с читаемым светлым текстом на `rgb(11,14,18)`. С ней всё в порядке.

Но `document.elementsFromPoint()` в центре первого поля возвращает сверху вниз:

```
IMG  →  SPAN.pz  →  DIV.shot  →  INPUT  →  FORM  →  ASIDE.cform
```

Картинка героя (`.shot` / `.pz`) рисуется **поверх** формы. У панели формы `position: static` и `z-index: auto`, своего контекста наложения она не создаёт, поэтому уходит под изображение.

Видно наружу только кнопку — она ниже нижней кромки картинки. Скриншот: `audit/probe/contact-inview.jpg`.

**Что это стоит:** `/contact` — страница с наибольшим числом входящих ссылок на сайте (94). Каждый посетитель, дошедший до неё, видит фотографию пляжа и кнопку без полей.

**Починка — одна строка:**

```css
.cform { position: relative; z-index: 2; }
.chero .shot, .chero .pz { z-index: 0; }
```

Форма на главной (`#rq`) этой проблемой **не затронута** — там над полем сверху лежит сам `INPUT`, порядок правильный. Баг локальный, только `/contact`.

### 2.2. Формы ничего не отправляют

Протестировано тремя проходами с реальной отправкой. Результат по обеим формам:

| Что проверялось | Главная `#rq` | Контакты `#cf` |
|---|---|---|
| Атрибут `action` | нет | нет |
| Метод | GET (по умолчанию) | GET |
| Атрибуты `name` у полей | **ни у одного** | **ни у одного** |
| Обязательные поля (`required`) | **ни одного** | ни одного |
| `novalidate` на форме | да | да |
| Отправка пустой формы | **проходит валидацию** | **проходит валидацию** |
| Невалидный e-mail | блокируется (тип `email`) | поля e-mail нет вообще |
| POST при отправке | **0** | **0** |
| Единственный POST на странице | телеметрия Cloudflare `/cdn-cgi/rum` | то же |
| Капча / honeypot | нет | нет |

Кнопка на контактах прямо называется **«Compose the email»**, и после нажатия появляется текст:

> «Opening your email client. If nothing happens, write to info@ispgroupgc.com with the same details.»

На главной под формой честно написано: «Nothing is sent from this page and nothing is stored here.»

**Почему это дорого:**

- `mailto:` молча не срабатывает у всех, у кого не зарегистрирован почтовый клиент по умолчанию — а это основная масса корпоративных десктопов с веб-Gmail, Chromebook'и, часть рабочих станций с политиками. Человек жмёт кнопку, не происходит ничего, он уходит.
- Даже там, где клиент открывается, остаётся второй барьер: письмо надо ещё отправить вручную.
- Заявка нигде не сохраняется. Нет CRM, нет лога, нет уведомления, нет возможности посчитать конверсию.
- Поля `Name`, `Work e-mail`, `Company`, `Country` собираются и тут же выбрасываются в тело письма.
- Пустую форму можно «отправить» — ни одно поле не обязательное.
- Адрес `info@ispgroupgc.com` открыто лежит в `mailto:` — корм для парсеров.

**Что делать:**

1. Проставить всем полям `name`, ключевым — `required`, снять `novalidate`.
2. Поднять реальный приём. Инфраструктура уже на Cloudflare, поэтому дешевле всего Pages Function / Worker, который принимает POST и шлёт письмо через транзакционный API (Postmark, Resend) — почта домена уже на Google Workspace, SPF и DKIM настроены. Если не хочется кода — Formspree, Basin или Web3Forms, подключаются за полчаса.
3. Писать заявку ещё и в таблицу или CRM, а не только в почту.
4. Добавить Cloudflare Turnstile (бесплатен, та же панель) и скрытое honeypot-поле.
5. `mailto:` оставить, но как запасную ссылку под формой, а не как основное действие.
6. Экран благодарности отдельным URL (`/thanks`) — иначе конверсию нечем мерить.

### 2.3. Нет телефона

На сайте нет ни одной ссылки `tel:`. Для торговли с Западной Африкой, Турцией и Китаем отсутствие телефона и WhatsApp — не стилистический выбор, а потеря половины входящих. Там так работают.

В `schema.org` блоке `Organization` поля `telephone` тоже нет.

### 2.4. Адрес указан по-разному

- Главная, надпись над заголовком: **«ISP GROUP LLC · Aventura, Florida»**
- `schema.org`, `/about`, `/contact`, футер: **«16395 Biscayne Blvd, North Miami Beach, FL 33160»**

Авентура и Норт-Майами-Бич — разные города. Расхождение NAP (Name–Address–Phone) бьёт и по доверию, и по локальному ранжированию, если будет заводиться Google Business Profile. Привести к одному варианту везде.

- **Картинка героя растянута в 2.6 раза.** `port-noir.webp` имеет натуральный размер 546×682, а показывается в 1440×900. Отсюда мыло на главной, хорошо заметное на снимке `audit/views/home-d-00.jpg`. Нужен исходник хотя бы 1600 px по ширине в AVIF/WebP (~80–120 КБ). Он уже стоит с `fetchpriority="high"` и `preload`, так что на LCP заметно не повлияет, а картинка станет резкой.
- `apple-touch-icon.png` и `site.webmanifest` отдают 404. Фавикон встроен как data-URI SVG, в браузере работает, но на iOS при добавлении на домашний экран иконки не будет.

## 4. SEO

### Что сделано правильно

- `robots.txt` корректный, со ссылкой на `sitemap.xml`; карта сайта валидная, с `lastmod` и приоритетами.
- `canonical` проставлен на **всех** 20 проверенных страницах, абсолютными URL.
- `meta robots: index,follow,max-image-preview:large` везде.
- Title 19–58 символов, description 112–186 — все в пределах нормы, **ни одного дубля**.
- Open Graph и Twitter Card на каждой странице, со своей картинкой; все проверенные `og:image` отдают 200.
- `schema.org`: три блока на главной — `Organization` (с адресом, датой основания, `knowsAbout`), `WebSite`, `Service` с `hasOfferCatalog` и `areaServed`. Это заметно выше среднего по рынку.
- **У всех изображений на всех 20 страницах есть `alt`.** Ноль пропусков — редкость.
- Объём: 850–2 570 слов на странице. Весь контент в серверном HTML, без зависимости от JS для индексации.
- `google-site-verification` в TXT-записи — Search Console, судя по всему, уже подключён.

### Что исправить

**1. `www` не редиректится.** `https://www.ispgroupgc.com/` отдаёт 200, а не 301 на апекс. Canonical жёстко указывает на апекс, поэтому Google склеит, но правильнее поставить Redirect Rule в Cloudflare — иначе сигналы двоятся во внешних инструментах и в ссылках.

**2. Пять страниц-сирот.** В sitemap есть, но из меню и с главной на них нет ни одной ссылки:

```
/fr                      /contact-fr
/afrique-ouest           /certificat-veterinaire
/decoupes-volaille
```

Это французская версия — и это ровно тот язык, на котором говорит Западная Африка, один из четырёх заявленных коридоров. Сейчас этот раздел существует, но попасть в него можно только из карты сайта.

**3. `hreflang` неполный.** Есть на `/` и `/contact` (en / fr / x-default, взаимно корректные). На `/services`, `/supply`, `/building-materials` — нет. Проверить пары для `/west-africa` ↔ `/afrique-ouest` и остальных.

**4. Нет переключателя языка в интерфейсе.** Следствие п. 2.

**5. Ноль внешних исходящих ссылок на весь сайт.** Руководство по Инкотермс без ссылки на ICC, страница про коды ТН ВЭД без ссылки на WCO, раздел про ветеринарные сертификаты без ссылки на реестры. Для тематической авторитетности и для цитирования в AI-ответах это заметный минус — сайт выглядит замкнутым на себя.

**6. Нарушен порядок заголовков** — единственная претензия Lighthouse, по одному случаю на страницу.

**7. Домену 6 месяцев** (создан 09.04.2026, регистратор Cloudflare). Сайта нет в выдаче вообще — ни по бренду, ни по запросам. Это нормальная фаза, но она означает, что весь текущий трафик — прямой и реферальный, и мерить SEO пока нечего.

## 5. Видимость в AI-ответах

Что работает в плюс: весь контент отдаётся в серверном HTML (проверено запросом с User-Agent Googlebot — текст на месте целиком), семантическая разметка чистая, `schema.org` богатый, на страницах есть явные блоки FAQ с вопросами в той формулировке, в какой их задают. Это именно то, что AI-краулеры извлекают легче всего.

Что мешает:

- **Нет `llms.txt`** — отдаёт 404.
- **Нет внешних ссылок и нет цитируемых источников.** Модели охотнее опираются на страницы, которые ссылаются на первоисточники.
- **Нет подтверждаемой сущности.** Компании нет ни в одном внешнем источнике: поиск по «ISP Group GC» и «ISP Group general contractor Florida» не находит ничего, кроме посторонних фирм. Для модели это означает, что утверждения сайта нечем подтвердить, и в ответ она его не поставит.
- Нет авторства у руководств — ни имени, ни квалификации.

## 6. Визуал

### Сильные стороны

Арт-дирекшн действительно хороший: тёмная палитра `#080A0D` / `#F4F3EF`, акцент бирюзовый, связка из трёх гарнитур (Schibsted Grotesk для интерфейса, Newsreader для академических заголовков, IBM Plex Mono для технических подписей) — выдержана последовательно. Герой с H1 в 132 px на фотографии портовых кранов выглядит дорого. Макет ограничен 1480 px, сетка аккуратная.

### Проблемы

**1. Провалы контраста в середине скролла.** Секция «FROM THE SOURCE.» — светло-серый заголовок на светло-сером фоне каменной текстуры, читается плохо; надпись «01 — Origin» над ним практически невидима (`audit/views/home-d-03.jpg`). Lighthouse это не ловит, потому что проверяет только исходное состояние, а здесь виновата промежуточная фаза скролл-анимации: затемняющая подложка в этот момент не применена.

То же на `/contact`: абзац «Product, quantity and destination port…» идёт серым по фотографии небоскрёбов и наезжает на их контур.

**2. Круглая «линза» перекрывает текст.** В секции «FIND THE RIGHT SOURCE.» декоративный круглый элемент наезжает на заголовок и на строки списка (`audit/views/home-d-05.jpg`).

**3. На мобильной главной нет навигации.** В шапке только логотип и кнопка «Request a quote». Ни меню, ни гамбургера — проверено на двух позициях скролла. На внутренних страницах иконки поиска и меню есть, на главной — нет. Попасть в разделы с мобильной главной можно только долистав до футера, а это 13 595 px.

**4. Страница чудовищно длинная.** Главная — **16 376 px на десктопе** (18 экранов) и 13 595 px на мобильном (20 экранов). При этом под `prefers-reduced-motion` та же страница укладывается в **7 209 px**. То есть **9 167 px, 56% высоты главной, — это чистые леса под скролл-анимации**, по которым пользователь просто крутит колесо.

Для B2B-покупателя, который пришёл за ценой, это дорого. Вариант под reduced-motion — по сути готовая «быстрая» раскладка; её разумно сделать основной хотя бы на мобильном.

**5. Без JavaScript страница пустая.** На главной **19 из 26** блоков с анимацией появления остаются с `opacity: 0`; на `/contact` — **4 из 4**, то есть весь контент страницы. Для Google это не проблема (он исполняет JS, а текст и так в HTML), но любой сбой скрипта, блокировщик или корпоративный прокси превращают страницу в пустой экран. Страхуется одной вставкой:

```html
<noscript><style>.fade,.content,[data-reveal]{opacity:1!important;transform:none!important}</style></noscript>
```

**6. Мелкие цели нажатия.** 19 элементов на мобильной главной и 23 на `/services` ниже 44 px по одной из сторон — в основном ссылки футера высотой 28 px.

## 7. Тексты — самая сильная часть сайта

Копирайтинг заметно выше рынка. Он конкретный, с позицией и без наполнителя:

- «A container is the last twenty per cent of the job.»
- «An offer from a producer that cannot legally ship to your destination is not an offer, whatever the number on it.»
- «An agent introduces you to a factory and takes a percentage. If the factory fails, the agent is a witness.»
- «A buyer who is told the truth about a twelve week lead time plans around it. A buyer who is told six and gets twelve does not come back.»

Правильно сделано:

- Есть раздел **«What we do not do»** — сильный приём доверия, почти никто так не пишет.
- Позиционирование («принципал, а не брокер») проведено через весь сайт, а не объявлено один раз.
- Бизнес объяснён через **коридор, а не каталог** — это настоящая мысль, а не маркетинговая обёртка.
- FAQ сформулированы как реальные вопросы покупателя: «Who carries the risk if the factory does not ship?»
- Сроки названы числами: ответ за 1 рабочий день, landed price за ~10 рабочих дней.
- Явно сказано, что минимального заказа нет в привычном виде, работа идёт полными контейнерами, и почему.

Что добавить:

- **Ни одной цифры о самой компании.** «Twenty years of supply work» — и всё: ни оборота, ни числа отгрузок, ни тоннажа, ни числа поставщиков в базе.
- **Ни одного кейса.** Нужны 2–3 обезличенных разбора: что везли, откуда, сколько шло, что пошло не так и как решили. В этом бизнесе продаёт именно третий пункт.
- Заявлено «двадцать лет», при этом домену полгода и компании нет ни в одном внешнем источнике. Само по себе это нормально, но без подтверждений выглядит как заявка без обеспечения.

## 8. Доверие — самый большой коммерческий разрыв

Сайт просит незнакомого человека завести внешнеторговый контракт на контейнерные партии. При этом на нём нет:

| Чего нет | Почему это важно именно здесь |
|---|---|
| Номера регистрации на Sunbiz | Проверяется за 30 секунд, снимает первый вопрос |
| EIN / D-U-N-S | Первое, что спрашивает комплаенс покупателя |
| Телефона | См. 2.3 |
| Имён и фотографий людей | Все фотографии на сайте — сток CC0, это указано в титрах |
| Банковской референции или сведений о торговом финансировании | Ключевой вопрос при предоплате |
| Кейсов, отзывов, референс-листа | Нечем подтвердить двадцать лет |
| Членства в отраслевых объединениях | Внешний сигнал |
| Профиля в LinkedIn и Google Business Profile | Компании нет в выдаче вообще |

**DMARC стоит в `p=none`.** SPF и DKIM настроены корректно, но политика в режиме наблюдения — то есть подделка писем от вашего домена технически не блокируется. Для компании, которая переписывается о платежах по внешнеторговым контрактам, это прямой риск: подмена реквизитов в письме — самая массовая схема мошенничества в этой отрасли. Перевести в `p=quarantine`, затем в `p=reject`.

## 10. Как это проверялось

Прямой доступ к сайту из рабочей среды закрыт: прокси отдаёт 403 на CONNECT, DNS в песочнице не резолвит. Поэтому весь обход выполнялся на раннере GitHub Actions с открытым интернетом, а результаты коммитились в ветку. Воркфлоу и скрипты лежат в репозитории:

- `.github/workflows/site-audit.yml` + `scripts/audit/audit.mjs` — обход, метаданные, Lighthouse
- `.github/workflows/form-test.yml` + `scripts/audit/forms.mjs` — тест форм, включая реальную отправку
- `.github/workflows/visual-audit.yml` + `scripts/audit/visual.mjs` — скриншоты по вьюпортам, ассеты, DNS
- `.github/workflows/probe-audit.yml` + `scripts/audit/probe.mjs` — вычисленные стили, рендер без JS, reduced-motion

Сырые данные: `audit/report.json`, `audit/forms-report.json`, `audit/visual-report.json`, `audit/probe-report.json`.
Скриншоты: `audit/views/` (по вьюпортам), `audit/forms/` (до и после отправки), `audit/probe/`, `audit/shots/`.

**Тестовая заявка была отправлена** с явно помеченными данными: имя `TEST - site audit (ignore)`, почта `test@example.com` (зарезервированный домен), телефон `305-555-0142` (зарезервированный диапазон), текст «AUTOMATED TEST SUBMISSION — please ignore». Поскольку формы работают через `mailto:`, в почтовый ящик ничего не ушло: письмо не формируется без почтового клиента. Это и есть результат теста.

**Что не проверялось:** позиции в выдаче и объёмы запросов по гео-фильтру, индексация в Search Console (нет доступа), поведение форм на реальных мобильных устройствах, содержимое французских страниц, нагрузочное тестирование.
